# AvtoSlot

Сервис записи в автосервис. Клиент выбирает автомобиль, услуги и время визита, администратор управляет заявками, а мастер видит назначенные работы.

Проект охватывает весь путь заявки: от выбора услуг до завершения работы и отзыва. Есть публичный сайт, личный кабинет, панели администратора и мастера. Всё приложение, включая API, находится в одном Next.js-проекте.

## Что можно сделать

**Клиент:** зарегистрироваться, добавить несколько автомобилей, выбрать услуги и свободное время, создать или отменить запись. В кабинете доступны история обслуживания, уведомления и отзывы после визита.

**Администратор:** просматривать и фильтровать заявки, менять статусы, переносить записи, редактировать услуги и цены, смотреть клиентов и загрузку мастеров.

**Мастер:** просматривать назначенные работы, менять их статус и оставлять комментарии.

Время записи рассчитывается по суммарной длительности выбранных услуг. При подборе мастера учитываются рабочие часы, существующие записи и заблокированные интервалы. Проверки доступа выполняются на стороне API; там же находятся валидация, ограничение частоты запросов и журнал действий.

## Стек

Next.js 16, React 19, TypeScript, Tailwind CSS 4, PostgreSQL 16 и Prisma. Формы используют React Hook Form и Zod, пароли хешируются через bcrypt, сессии подписываются с помощью `jose` и хранятся в HttpOnly-cookie.

Docker Compose поднимает PostgreSQL. Само приложение при локальной разработке запускается через npm.

## Локальный запуск

Понадобятся Node.js 24, npm и Docker с Compose. Команды ниже рассчитаны на отдельную локальную базу для знакомства с проектом.

```bash
git clone https://github.com/Aoruszy/autoservice-project.git
cd autoservice-project
```

Создайте в корне `.env` **до установки зависимостей**: конфигурация Prisma читает `DATABASE_URL` уже при генерации клиента.

```env
DATABASE_URL="postgresql://avtoslot:avtoslot_password@localhost:5433/avtoslot?schema=public"
JWT_SECRET="local-avtoslot-demo-secret-change-before-deploy"
NEXT_PUBLIC_APP_NAME="AvtoSlot"
```

Это настройки для локальной демонстрации. Порт PostgreSQL в Compose — `5433`.

```bash
npm ci
docker compose up -d postgres
```

Дождитесь готовности базы — состояние можно посмотреть через `docker compose ps`. Затем создайте таблицы из текущей Prisma-схемы, загрузите демо-данные и запустите приложение:

```bash
npm run db:push
npm run db:seed
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

`db:seed` очищает существующие данные и заполняет базу заново. Запускайте его только на демонстрационной базе.

Для локального запуска используется `db:push`, потому что сохранённые SQL-миграции пока не полностью отражают текущую схему. Перед развёртыванием на сервере нужно привести миграции в соответствие со схемой и проверить их на пустой базе. `db:push` не заменяет миграции рабочей БД.

## Демо-аккаунты

После заполнения базы доступны:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Администратор | `admin@avtoslot.ru` | `Demo12345!` |
| Клиент | `client@avtoslot.ru` | `Demo12345!` |
| Мастер | `master1@avtoslot.ru` | `Demo12345!` |

Для просмотра основного сценария войдите клиентом, создайте запись, затем откройте её под администратором и мастером. Эти учётные данные предназначены только для демо.

## Структура проекта

```text
src/app/             страницы и API
src/components/      формы, кабинеты и панели управления
src/lib/             авторизация, бронирование, валидация и аудит
prisma/schema.prisma модель данных
prisma/migrations/   SQL-миграции
prisma/seed.ts       демонстрационные данные
docker-compose.yml   локальный PostgreSQL
```

Логика расчёта свободных интервалов находится в `src/lib/booking.ts`, проверки входных данных — в `src/lib/validators.ts`. При создании заявки её данные, уведомления и запись в журнале сохраняются в одной транзакции.

## Проверка и сборка

```bash
npm run lint
npm run build
```

Для сборки нужны настроенные переменные окружения. После успешной сборки приложение запускается командой `npm run start`. При `NODE_ENV=production` нужен собственный `JWT_SECRET` длиной не менее 32 символов.

Автоматических тестов бизнес-сценариев пока нет. В первую очередь стоит покрыть расчёт интервалов, права разных ролей, создание и перенос записей.

## Текущие ограничения

Это демонстрационная версия. Онлайн-оплата, SMS и email-уведомления, работа с несколькими филиалами пока не реализованы.

Проверка занятости слота выполняется до транзакции создания записи. При одновременных запросах это оставляет возможность двойного бронирования. Следующий шаг — обеспечить защиту на уровне БД и добавить тест с конкурентными запросами.

Также нужно обновить миграции и разделить крупные компоненты кабинета и панели администратора. Перед публичным развёртыванием следует заменить локальные пароли и секреты и настроить HTTPS.
